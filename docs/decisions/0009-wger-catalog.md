# 0009 – wger as a larger exercise catalog

**Status:** proposed (recommendation; the owner confirms the open question below) · 2026-10-20

**Context:** PRD §6.3 / §26.5 defer evaluating [wger](https://wger.de/) until after P0. The seed catalog (~100 exercises, self-written, ADR 0005) has no third-party data. This ADR checks wger's schema, licenses, size and id mapping against the offline-first, no-backend rules. Figures below come from the public API (`wger.de/api/v2`, English only) on 2026-10-20 and will drift.

**Findings**
- **Schema.** `exerciseinfo` returns one record per exercise: `uuid`, category, `muscles` / `muscles_secondary`, `equipment`, `variation_group`, per-language `translations` (name, HTML `description`, aliases), `images`, `videos`, and licence fields. The ids are wger's own integers and uuids, and its muscle/equipment taxonomy differs from ours (`src/lib/types.ts`), so a mapping table is required. There is no exercise-type field (reps / duration / distance), so we would have to infer it. 932 exercises have an English translation; 20 of those have an empty description.
- **Licence per data type.** Every exercise and translation carries its own licence and `license_author`: CC-BY-SA 4.0 (779), CC-BY-SA 3.0 (132), CC0 (21). Images carry their own licence (CC-BY-SA 4 or 3; five record a `license_derivative_source_url`, i.e. derived from another work, e.g. Wikipedia), and 46 of 383 images are flagged `is_ai_generated`. Videos (78) are licensed per file. The wger application is AGPL; the AGPL does not cover the data. Attribution requires author, licence and link per item. Share-Alike means adaptations of text or images must be offered under the same licence, which is incompatible with silently merging them into this project's own seed file.
- **Size.** English name and description text is about 400 KB raw (about 100 KB gzipped). Images: 383 files, roughly 35 KB each (about 13 MB). Videos: 78 files totalling about 3.5 GB, which is unusable offline. The shell precache budget (PRD §21) and iOS storage eviction make bundling media a poor fit.
- **Offline.** Runtime calls to wger are unacceptable (PRD §6.3). Anything adopted must be a build-time snapshot, shipped as static files.
- **Ids.** Existing seed ids are permanent snake_case and referenced by history, backups and import files (`docs/data-model.md`). wger ids must never replace them. An imported exercise would get a new id `wger_<wger uuid, hyphens → underscores>` (matches `/^[a-z0-9_]+$/`); an exercise that duplicates a seed entry is recorded as an alias of the seed id, not added as a second row.
- **Quality.** Text is user-contributed, HTML (must be sanitized or converted to plain text; never `{@html}`), uneven in language and accuracy, and often duplicates our seed.

**Decision (recommended):**
1. **Do not make wger part of the default catalog or the app bundle.** No wger text, images or video ship with the core app. The self-written seed remains the single built-in source; `docs/attribution.md` stays "no third-party data bundled".
2. **Never bundle video; do not bundle images.** Size, per-file licences, Share-Alike and AI-generated content outweigh the benefit. The exercise detail page keeps its no-media fallback (PRD §6.3).
3. **If a larger catalog is wanted, ship it as an optional, separately versioned "Extended catalog" pack, text-only**, generated by a build-time script from a pinned API snapshot, loaded on demand (static file, cached by the service worker after the user opts in, never fetched at lookup time). Its entries have `source` = `{ name: 'wger', licence, author, url }` and `isCustom: false`; the pack file keeps its CC-BY-SA terms and the UI shows an attribution screen listing author/licence/link per exercise. Pack entries never overwrite seed rows or user state, and history snapshots names as usual (ADR 0004). Entries with CC-BY-SA text can be removed without touching history because they are referenced by id only.
4. **Do this only on demand.** Trigger: users repeatedly hit "exercise not found" after P0 and custom exercises/merge (PRD §6.4) prove insufficient. Until then, no work.

**Alternatives considered:** bundle everything (rejected: 3.5 GB video, Share-Alike on media, AI-generated images); runtime API (violates offline rule); names/muscles only with no descriptions (smaller licensing surface and probably fine, but adds a mapping effort with little value over custom exercises, so it is folded into option 3 as a trim level); a different dataset (not evaluated here).

**Open question for the owner:** is a CC-BY-SA text pack acceptable for this repo's `LICENSE` and distribution plans? If not, the answer is option 1 only. This is not legal advice; confirm before shipping any pack.

**Follow-ups (only if option 3 is approved, create then):** (a) build-time snapshot + Zod-validated converter with category/muscle/equipment mapping and type inference; (b) lazy pack loader + service-worker caching + opt-in setting; (c) attribution screen; (d) duplicate detection against the seed and tests that seed ids stay stable. #119 (`T8.33`) is unblocked by this decision.

**Consequences:** No change to code, bundle size or data today. The decision avoids a licensing obligation we cannot satisfy cheaply, and leaves a bounded path to a bigger catalog if real usage demands it.
