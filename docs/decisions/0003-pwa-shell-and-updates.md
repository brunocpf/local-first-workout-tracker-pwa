# 0003 – PWA shell, updates, hosting and tooling

**Status:** accepted · 2026-10-20

**Context:** The app must work in desktop browsers, Android Chrome and iOS Safari (installed to the Home Screen), fully offline after the first load, on a static host, and must never lose or disrupt an in-progress workout.

**Decision:**
- **Navigation fallback.** The service worker answers *every* navigation with the cached app shell (adapter-static's SPA fallback page `404.html`), not only when the network fails; the client router then renders the route. A static host's 404 for `/history` is never shown. The shell is fetched by hand at install and stored as a 200 response, because hosts serve the fallback page with a 404 status and `cache.addAll()` rejects that. Other same-origin GETs are cache-first with `ignoreVary` (module requests send `Origin`; dev servers reply `Vary: Origin`). All URLs resolve against the SW scope, so any base path works.
- **Deferred updates.** No `skipWaiting()` on install: a new SW waits so it cannot delete route chunks the open page still needs. It activates on a `{type: "SKIP_WAITING"}` message. SvelteKit's `updated` (`$app/state`, polled every 5 min by `kit.version.pollInterval`, plus focus/visibility checks) drives an "Update available — Reload" banner (`src/lib/components/UpdateBanner.svelte`); the button asks the registration to update, posts `SKIP_WAITING` and reloads on `controllerchange`. `setCanUpdate(false)` in `src/lib/pwa/update.svelte.ts` is the seam for hiding the banner during an active session (to be wired when session logic exists).
- **Base path / hosting.** `paths.base` comes from `BASE_PATH` (empty = domain root; `/repo-name` for a GitHub Pages project site). Nav links use `resolve()`; the manifest uses `"./"` for `id`, `start_url`, `scope` and icon URLs so it works at any base. `adapter-static` `fallback: "404.html"` is what GitHub Pages serves for unknown paths, so deep-link reloads work before the SW is installed (the response carries a 404 status, which browsers ignore for rendering).
- **Origin permanence.** IndexedDB and the service worker are bound to the origin. `<owner>.github.io/<repo>` works for now, but the production origin should be a permanent custom domain: moving origin later strands users' data (export/import is the only migration path).
- **Deploy.** `.github/workflows/deploy.yml` builds with `BASE_PATH=/${{ github.event.repository.name }}` and deploys `build/` to GitHub Pages on push to `main` / manual dispatch, with per-job least-privilege permissions. With a custom domain at the root, set `BASE_PATH` to empty.
- **Icons.** iOS ignores SVG `apple-touch-icon`, so PNGs are committed in `static/` (180 full-bleed apple-touch, 192/512 `any`, 512 `maskable` with the glyph inside the safe zone), generated from `icon.svg` by `scripts/generate-icons.mjs` (temporary `sharp`, not a dependency). Both `mobile-web-app-capable` and the Apple meta are set.
- **CSP.** `kit.csp` (`mode: "auto"` → hashes, emitted as a `<meta>` tag in the static pages): `default-src 'self'`, no remote scripts, `img-src 'self' data: blob:`, `connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`. `style-src-attr 'unsafe-inline'` is allowed because Svelte/Kit set `style` attributes (e.g. the route announcer); stylesheets and `<style>` remain restricted. `frame-ancestors` cannot be set via meta and is skipped. An e2e test fails on any console error, which includes CSP violations.
- **Lint.** ESLint flat config with typescript-eslint and eslint-plugin-svelte; `svelte/no-at-html-tags` is an error to enforce "never render imported HTML". `npm run lint`.
- **E2E.** Playwright against the production build (`vite build && vite preview`; the SW only exists there), in Desktop Chromium, Mobile Chrome (Pixel 7) and Mobile Safari (WebKit, iPhone 15): load + tabs, deep-link reload, offline reload. `npm run test:e2e`; CI installs browsers with deps. WebKit is an approximation of iOS Safari, not a replacement for checking an installed PWA on a device.
- **`#lib/*` imports.** Resolution is `#lib/*` → `src/lib/*.ts`; import files, not folders (`#lib/storage/db`), and the empty placeholder `index.ts` modules were removed. Components under `src/lib/components/` import via `#lib/components/*.svelte`. A blanket `#lib/*.svelte` mapping was rejected: it would also capture rune modules such as `#lib/pwa/update.svelte` (`update.svelte.ts`).

**Consequences:** New versions reach users only after an explicit reload, so old and new clients can briefly coexist with different code against the same IndexedDB — schema migrations must tolerate that (see data-model docs). The e2e suite adds ~1 min and a Playwright browser download to CI. Revisit Workbox/`@vite-pwa/sveltekit` when it supports Kit 3.
