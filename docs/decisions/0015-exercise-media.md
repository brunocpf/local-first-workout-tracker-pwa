# 0015 – Exercise demonstration media (GIFs, video, images)

**Status:** proposed (recommendation; the owner confirms the open question below) · 2026-10-21

**Context:** The owner asked whether the exercise detail page (`src/routes/exercises/[id]/+page.svelte`) could show a GIF, video or image from a free resource. Today it shows type, equipment, muscles, instructions, form cues and an optional "External guide" link (an `external_link` in `exercise.media` or `source.sourceUrl`, opened in the browser). PRD §6.3 allows media "only where legally usable" and says missing media must never show a broken placeholder. Constraints: works offline (ADR 0001); CSP `default-src 'self'`, `img-src 'self' data: blob:`, `connect-src 'self'`, no `frame-src`, so no third-party embeds (ADR 0003, `vite.config.ts`); no backend except the push relay (ADR 0014); the service worker precaches every file in `immutable`/`assets`/`prerendered` under a cache named per version, so anything put in `static/` is downloaded on install and again on every app update (the whole build is about 1.3 MB today); the code is MIT and may ship commercially (`docs/licenses.md`, #225), so nothing share-alike or non-commercial may be mixed into the bundle; iOS can evict storage and keeps the installed app's storage separate from Safari's (`docs/browser-limitations.md`). Figures below were measured on 2026-10-21 and will drift.

**Our own options**

- **Text only (current).** Instructions and form cues written for the project, plus the user-controlled external link. No cost, no licence surface, works offline. Its weakness is that a movement is easier to see than to read.
- **Self-authored diagrams.** Simple two-position line drawings (start and end) drawn for the project as SVG path data, in the style of `src/lib/icons.ts`: `stroke="currentColor"` so they use design tokens and dark mode, about 1–3 KB each, roughly 150–300 KB for the whole seed. They would be MIT (or project-owned), so they can ship commercially, need no attribution, work offline and need no CSP change. Cost: drawing them, which is real work (each must show the movement correctly), and they should be done for the most-used exercises first. Precaching them all adds about 0.2 MB to every install and update, which is acceptable; if that grows, they can move to one lazily loaded chunk.
- **A link out, not an embed.** The page already opens an external guide in the browser. A "Find a demo video" link that opens a search for the exercise name on YouTube (in the browser, not in the app) gives users video without any embed, storage, CSP change or licence question for us; it only works online, which the link can say.

**Decision (recommended):**

1. **Do not bundle, embed or download third-party exercise media.** free-exercise-db images are scraped and not licensed; ExerciseDB and MuscleWiki forbid local storage and need keys or a backend; YouTube forbids caching and needs a third-party frame. None of these fits an offline, backend-free, commercially distributable PWA. `docs/attribution.md` stays "no third-party data bundled".
2. **Keep text cues as the baseline, and add an external "Find a demo video" link** on the detail page next to the existing guide link: `https://www.youtube.com/results?search_query=<exercise name> exercise form`, opened with `target="_blank" rel="noopener noreferrer"` like the guide link, hidden or labelled "needs a connection" when offline. The URL contains only the exercise name, never user data. This needs no ADR 0003 change.
3. **If in-app visuals are wanted, draw our own SVG diagrams**, starting with the 20–30 most-logged seed exercises, as path data in a `src/lib/catalog/diagrams.ts` module keyed by seed id. An exercise without a diagram shows nothing (PRD §6.3). Custom exercises have no diagram. Diagrams are part of the app, not of the user's data, so they are not in backups and need no migration.
4. **wger images stay where ADR 0009 left them:** not bundled. If the optional CC-BY-SA "Extended catalog" pack is ever built, images are not part of it; reconsider only if the owner accepts CC-BY-SA media and only for files with a named author.

**Why not an optional download pack.** A pack of wger images (about 2–4 MB of thumbnails for the 44 matches) would be the only legal third-party path. Following the ADR 0010 precedent it would mean: a build-time snapshot published as a separate static file set, downloaded only after opt-in, kept in its own Cache Storage cache (not the per-version app cache, so updates don't re-download it), never in the JSON backup (it can be fetched again), with an attribution screen per image and the CC-BY-SA terms kept with the files. Eviction would only remove pictures, not data, and Settings would need to show its size and a "remove" action. That is a fair amount of machinery for pictures of 4 in 10 seed exercises in mixed styles, from a set where 87 photos have no named author, so it is not recommended.

**Alternatives considered:** each source above; paid licensed packs such as Vital Animations ([exercisedb-pro/exercisedb-dataset](https://github.com/exercisedb-pro/exercisedb-dataset)) or [wrkout.xyz](https://wrkout.xyz/) (cost money and the licence would need its own review; out of scope for a no-recurring-cost app, PRD §27); Wikimedia Commons (per-file licences, mostly share-alike, uneven coverage; same problems as wger, not measured); user-added images or links per exercise (the `media` field already allows an `external_link`; storing user images would follow ADR 0010 and is not worth it for demos).

**Open question for the owner:** is a text + link-out page enough, or are self-drawn diagrams worth the drawing effort? If neither is wanted, nothing changes. This is not legal advice; the licence readings above are from the cited pages on 2026-10-21.

**Follow-ups (only if approved, create then):** (a) "Find a demo video" link on the detail page with an offline state and an e2e check that no request leaves the origin; (b) diagram format, a few sample diagrams and a review checklist for correctness; (c) diagrams for the most-used seed exercises, then the rest as time allows.

**Consequences:** No code, bundle, CSP or data-format change today. The app keeps no third-party media obligations and stays fully offline; users who want to watch a video get one in their browser with one tap, at the cost of leaving the app and needing a connection.
