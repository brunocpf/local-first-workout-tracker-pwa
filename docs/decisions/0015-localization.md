# 0015 – Localization (en, pt-BR)

**Status:** accepted · 2026-10-21

**Context:** The app should be usable in Brazilian Portuguese, including the built-in exercise catalog. It is a static, offline SPA, so there is no server-side locale negotiation and no need for a heavy i18n library.

**Decision:**
- **Catalogs:** UI text lives in per-area files `src/lib/messages.<area>.ts`, each built with `defineMessages({ en, ptBR })`. The type requires both locales to define exactly the same keys, and `src/lib/messages.ts` merges the areas (`MessageKey`, `PluralKey`). Keys are flat and dotted (`workout.addExercise`). Plural messages are `<key>.one` / `<key>.other` pairs.
- **Runtime:** `src/lib/i18n.svelte.ts` exposes `t(key, params?)` (fills `{name}` placeholders), `tn(key, n, params?)` (plural via `Intl.PluralRules`; pt-BR counts 0 as "one"), `intlLocale()` for `Intl` / `toLocale*String`, `i18n.locale` and `setLocale()`. All are reactive. It reads `locale` from the shared `settings` store, which `+layout.ts` loads before first render; the layout sets `<html lang>`.
- **Preference:** `UserSettings.locale` is optional, `"system" | "en" | "pt-BR"`, default `"system"`. `"system"` resolves from `navigator.languages`: any `pt*` tag gives pt-BR, everything else English. Older backups restore as `"system"`. Settings has a Language control.
- **Built-in exercises:** `src/lib/catalog/seed.pt-BR.ts` holds the pt-BR name, aliases, instructions and form cues for every seed id. It is a **display-only overlay**: stored rows, history snapshots and backups keep the English text, and ids never change. `localizeExercise(s)` (`catalog/localize.ts`) returns display copies for pt-BR: the English name and aliases stay searchable as aliases, and a field the user edited (it differs from the seed) is kept as written. `exerciseLabel(id, snapshotName)` shows a built-in exercise's pt-BR name for session and routine snapshots that still hold the seed English name, without rewriting them. Display copies are never written back to storage. A test checks that every seed id has an entry and that names and aliases stay unique.
- **Vocabularies:** muscles, equipment, exercise types, set types, measurement kinds and weekdays are labelled through `catalog/labels.ts` (keys in `messages.vocab.ts`); ids outside the vocabulary (custom or imported) are humanized.
- **Formatting:** dates, numbers and durations use `Intl` with the app language (`#lib/format`, `intlLocale()`), not the browser's. Weights stay kg internally; decimal input accepts both `82.5` and `82,5`.
- **Not translated:** user and imported content (custom exercise names, routine and program names, notes), stored data, the AI prompt text the generator produces (it is addressed to an AI and carries the English schema), the Diagnostics page and the internal `/dev` pages, and messages built inside parsers and validators (import parse errors and warnings). A few well-known domain messages are mapped by `errorText()`; anything else is shown as it comes.
- **Adding a language:** add a catalog per area typed through `defineMessages` (a `ptBR`-style key next to `ptBR`), extend `Locale` / `LocaleSetting`, `resolveLocale` and the Language control, and add a `seed.<locale>.ts` overlay.

**Consequences:** Every new user-visible string needs a key in both locales. `static/manifest.webmanifest` stays English (a static file; revisit if localized install names matter). Parser-level import messages stay English until they are given codes.
